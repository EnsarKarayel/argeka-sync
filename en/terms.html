Terms of use

ARGEKA Sync is a technical self-hosted data transfer tool. Test runs, backups and permission checks should be completed before using it with production ERP or reporting databases.

Users are responsible for the database connections, SQL queries, target mappings and scheduled transfer jobs they create. A wrong filter, upsert key or table mapping can affect data quality.

The product is provided as a technical helper. Final validation depends on each organization's ERP model and business rules.

Before production use

Each transfer job runs according to the SQL query, mapping and write policy created by the user. ARGEKA Sync can make a well-designed flow easier to operate, but it cannot automatically correct an incorrect business rule. Users should test jobs, keep backups and review results before production use.

Jobs that use truncate reload, upsert or bulk writes need a rollback plan and documented validation steps.

Operational responsibility

Users are responsible for the flows they create. A transfer job can only be as reliable as its SQL query, mapping and write policy. Production jobs should have backups, test evidence and a rollback plan before they are scheduled.

For ERP, finance or quality data, validation should include normal records, exception records and records that are expected to fail. This keeps the tool aligned with real operational controls.
